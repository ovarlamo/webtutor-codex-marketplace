# Тестирование агента WebTutor

1. Прочитай инструкции клиентского репозитория и его пакетные скрипты.
2. Определи конкретный тест зарегистрированного агента или агента, запускаемого из файла, и способ его выполнения.
3. Сформулируй наблюдаемые критерии успеха и получи согласование проверки, если этого требуют правила репозитория.
4. Если существует `webtutor-codex.json` и требуется согласованное синхронное выполнение файла, используй `webtutor_run_script_file`, передавая относительный `relative_path` и абсолютный `project_root` активной рабочей области. Иначе используй предусмотренный репозиторием тест, не меняя его точку доступа.
5. При ошибке изучи полный JSON-ответ, включая `errors`, логи, результаты проверок и результат выполнения.
6. Изменяй только агента или зависимость в пределах текущей задачи, затем повторяй тот же тест.
7. Считай постановку в очередь или запуск в фоне незавершённым, пока предусмотренные репозиторием логи, данные или `last_run_date` не подтвердят завершение.

## Файловый тест с помощью MCP Bridge

При наличии согласованной конфигурации `webtutor-codex.json` для актуального
пути `web/server_agents/<agent_code>.js` вызывай
`webtutor_run_script_file` с `relative_path` относительно
`custom_root` и абсолютным `project_root` активного проекта.
Скрипты из `tools/` исполняются без загрузки переменных агента.

Bridge выполняет `EvalCodeUrl()`, а **не** `tools.start_agent()` или
`server_agent.run_agent()`. При запуске файла в одном из каталогов агентов
он выводит `agent_code` из имени файла и ищет `server_agents.code`:

- если карточка найдена, копирует её сохранённые `wvars` в `Param`
  как `wvar.value.Value` (без преобразования по `wvar.type`);
- если не найдена, файл всё равно выполняется, но без переменных карточки:
  проверь в ответе непустой `result.agent_id` прежде чем считать
  загрузку `wvars` подтверждённой;
- `Param` дополнительно содержит поля Bridge `log`, `logs`,
  `errors`, `assertions`, `result`; они не являются частью
  универсального контракта производственного `run_agent()`.

Для параметров обязательны проверка фактических значений `Param` и
обработка форматов одиночного ID и JSON-массива, определяемых макетом
карточки. См. [параметры серверного агента](../webtutor-reference/objects-and-globals.md#параметры-серверного-агента-server_agent).

Ответ `ok=true` подтверждает лишь отсутствие ошибок, записанных в
`Param.errors` (если сам `EvalCodeUrl()` не завершился исключением).
Поля `assertions` возвращаются отдельно; их смысл и критерий успеха
определяются тестом текущего проекта. Требуется проверить ожидаемые данные
и эффекты, а не только `ok`.

Файловый тест не проверяет управление потоком, расписание, служебные
метаданные, `role_id` и передачу `OBJECT_ID`/`OBJECTS_ID_STR`
при реальном запуске карточки. Полный тест зарегистрированного агента
использует только механизм, явно предусмотренный текущим репозиторием,
и отдельное согласование потенциальных побочных эффектов.

Репозиторий может предоставлять команду `npm run test:wt-agent` или более специализированную `test:*`, но общая база плагина не предполагает их наличия. Идентификаторы зарегистрированных агентов, `script_path`, `env`, базовый URL, корень пользовательского веб-каталога и диагностическая точка доступа должны определяться из клиентского репозитория. Сохраняй идентификаторы в строковом виде и не меняй источник кода рабочего агента исключительно ради тестирования.
