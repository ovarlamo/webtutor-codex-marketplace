# XQuery и данные WebTutor

## Модель данных

Официальная иерархия SP-XML:

```text
база данных → каталог → запись → поле записи
```

Все записи каталога создаются по одному шаблону и могут содержать только описанные в нем поля. Поэтому имя поля нельзя выводить из бизнес-названия или угадывать по другому каталогу.

## Поддерживаемая форма XQuery

Документация называет SP-XML XQuery узким подмножеством с дополнительными функциями и рекомендует эффективную форму:

```xquery
for $elem in catalog
where <condition>
order by $elem/field
return $elem
```

Пример серверного кода:

```javascript
var xquery =
    "for $elem in collaborators " +
    "where $elem/email=" + XQueryLiteral(email) + " " +
    "return $elem";

var collaborator = ArrayOptFirstElem(XQuery(xquery));
```

## Литералы и динамические условия

- Строки: `XQueryLiteral(value)`.
- Целые ID: сначала `OptInt(value)`, затем конкатенация только валидного числа.
- Даты: использовать документированный литерал/функцию `date(...)`; не вставлять локализованную строку даты.
- Boolean: в XQuery используются `true()` и `false()`.
- `null`, пустая строка и отсутствующее значение не считать эквивалентными.

Небезопасно:

```javascript
xquery = "for $elem in collaborators where $elem/email='" + email + "' return $elem";
```

Безопаснее:

```javascript
xquery = "for $elem in collaborators where $elem/email=" + XQueryLiteral(email) + " return $elem";
```

## XQuery и SQL — разные режимы

В проверенном серверном коде SQL, передаваемый в `XQuery()`, начинается с обязательного
префикса `sql:`:

```javascript
var rows = XQuery(
    "sql:SELECT TOP 1 1 AS is_found " +
    "FROM courses"
);
```

Без префикса строка разбирается не как SQL и может завершиться неинформативной
ошибкой исполнения. Это подтвержденная практика проекта для установленной
версии WebTutor, а не основание смешивать синтаксис SQL и XQuery.

Подробности и границы правила: [SQL через XQuery](sql-through-xquery.md).

Если текущий репозиторий объявляет совместимые read-only capabilities, перед написанием SQL сначала запросить структуру таблицы:

```powershell
npm run get-table-info -- table courses
```

Для read-only проверки типичная команда имеет форму:

```powershell
npm run db-query -- "SELECT TOP 10 id, name FROM courses"
```

Конкретные команды нужно подтвердить по инструкциям репозитория. Для сложного запроса использовать файловый режим capability, если он предусмотрен. После проверки SQL обязательно запустить тест всего агента или отчёта: успешный SQL ещё не подтверждает обработку результата в SP-XML.

## Результаты запросов

Результат `XQuery()` обычно обрабатывается как абстрактная последовательность:

```javascript
for (elem in XQuery(xquery))
{
    // elem — очередная запись/проекция.
}
```

Для одиночного результата использовать `ArrayOptFirstElem`, а отсутствие обрабатывать явно. Не обращаться к `[0]` до подтверждения, что конкретный результат является `JsArray`.

## Производительность и объем данных

- Фильтровать в запросе, а не после загрузки всего каталога.
- Возвращать только нужную запись или поле, когда это поддерживает сценарий.
- Ограничивать диагностические запросы минимальными столбцами и строками.
- Paging применять после понимания, где он выполняется: в БД или над уже загруженной последовательностью.
- Не строить XQuery в цикле, если данные можно получить одним ограниченным запросом.

## Специализированные функции XQuery

Официальный индекс включает `ForeignDispName`, `ForeignElem`, `Hier`, `IsHierChild`, `IsHierChildOrSelf`, `MatchSome`, `CatalogHierSubset`, `date`, `contains`, `doc-contains`, `true`, `false`, `null`.

Это платформенные расширения/поддерживаемые элементы подмножества. Перед применением открыть карточку конкретной функции: их семантика не обязана совпадать с одноименной функцией другой реализации XQuery.
