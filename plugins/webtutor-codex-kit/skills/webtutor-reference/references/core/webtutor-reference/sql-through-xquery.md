# SQL через XQuery

Этот документ описывает явный SQL-режим `XQuery("sql:SELECT ...")`. Для
диагностики SQL, который активный UniBridge формирует из обычного XQuery
`for ... in ... return ...`, эти два режима не смешивать. Inspect-only
процедуру из [profile 2025.2.1403](../../profiles/2025.2.1403/playbooks/inspect-xquery-generated-sql.md)
загружать только при подтверждённом совпадении версии; при неизвестной версии
core-правило `sql:` работает без profile.

## Проверенный контракт

SQL-строка, передаваемая в `XQuery()`, должна начинаться с `sql:`:

```javascript
var rows = XQuery(
    "sql:SELECT TOP 1 1 AS is_found " +
    "FROM courses"
);
```

Префикс выбирает SQL-режим платформы. Обычный XQuery префикса не использует.
Это универсальный контракт WebTutor. Runtime-проверка может выполняться
read-only SQL capability текущего клиентского репозитория, если она там
объявлена; конкретный диагностический endpoint не является частью плагина.

## Безопасный порядок работы

1. Получить фактическую структуру таблицы:
   `npm run get-table-info -- table <table_name>` через capability текущего репозитория.
2. Выбрать только необходимые столбцы и ограничить число строк.
3. Для значений использовать параметры проверенного шаблона либо безопасное
   построение литералов; не конкатенировать непроверенный ввод.
4. Проверить чистый SQL через `npm run db-query -- "<SELECT ...>"`.
5. Добавить `sql:` в строку, исполняемую через `XQuery()`.
6. Запустить соответствующий end-to-end тест, объявленный текущим репозиторием.

`db-query` принимает SQL без префикса, потому что диагностическая ручка сама
формирует платформенный вызов. Рабочий SP-XML-код должен содержать `sql:`.

## Проверка существования

Если нужно узнать только о наличии строки, не загружать все поля:

```sql
SELECT TOP 1 1 AS is_found
FROM courses
WHERE id = 123
```

Имя таблицы и поля в примере не является универсальной схемой. Перед переносом
в рабочий код проверить их через `get-table-info`.

## Диагностика

При неинформативной ошибке `unibridge` или сообщении об отсутствии объекта
сначала проверить:

- наличие `sql:` непосредственно в строке для `XQuery()`;
- что запрос содержит ровно один `SELECT`;
- корректность таблиц и типов полей;
- отсутствие потери точности 64-битных идентификаторов;
- обработку пустого результата до обращения к первой строке.

См. также [ошибки SQL-префикса](../troubleshooting/sql-prefix.md).
