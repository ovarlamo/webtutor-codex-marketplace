# Исследование системного объекта

Используй только предусмотренный репозиторием диагностический механизм чтения с разрешённым списком типов объектов и фиксированными параметрами. Никогда не отправляй в диагностическую точку доступа произвольный SP-XML-код, путь к глобальному объекту или вызов произвольного метода `tools`.

Если в репозитории доступна команда, аналогичная `get-system-info`, используй подстановочные значения из текущей задачи:

```powershell
npm run get-system-info -- custom-template <catalog_name>
npm run get-system-info -- custom-template <catalog_name> --top-id <top_id>
npm run get-system-info -- custom-template <catalog_name> --source-id <object_id>
```

Сохраняй все 64-битные идентификаторы как строки. Для дополнительных полей сравни реальные значения в `custom_elems` объекта с описаниями `fields` найденного шаблона; название, тип, обязательность и параметры справочников получай из возвращённого XML, а не предполагай их.

Если такой возможности нет, остановись и запроси разрешённый механизм исследования, вместо того чтобы создавать его в рамках не связанной с этим задачи.
