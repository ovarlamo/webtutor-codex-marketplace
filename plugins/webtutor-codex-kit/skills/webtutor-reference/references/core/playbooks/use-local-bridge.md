# Использование локального MCP Bridge

Используй этот способ только при наличии `webtutor-codex.json` в активном проекте. Ближайшая конфигурация в родительских каталогах относится к этому проекту; не ищи её в соседнем репозитории заказчика.

1. Прочитай инструкции текущей рабочей области и получи согласование проверок в работающей системе, если оно требуется.
2. При каждом вызове инструмента Bridge передавай в `project_root` абсолютный путь к корню активной рабочей области. Рабочий каталог процесса MCP — это корень установленного плагина; его нельзя использовать для определения клиентского проекта.
3. Вызови `webtutor_ping`, если подключение или конфигурация ещё не подтверждены.
4. Используй только поддерживаемые операции:
   - `webtutor_get_table_info` — получение метаданных таблицы;
   - `webtutor_get_object_info` — получение `TopElem.Xml` с идентификатором в строковом виде;
   - `webtutor_run_agent_file` — согласованный запуск из прежнего каталога `agents/`;
   - `webtutor_run_script_file` — согласованное выполнение файла по пути относительно проекта.
5. Изучи полный ответ с полями `errors`, `logs`, `assertions` и `result`.
6. Если конфигурация или Bridge недоступны, используй только резервный механизм, предусмотренный репозиторием того же клиента.

`webtutor_run_agent_file` и `webtutor_run_script_file` могут выполнять бизнес-код и не являются операциями только для чтения. При наличии соответствующего серверного агента Bridge загружает его `wvars`, но не запускает рабочие агенты через `tools.start_agent()`.
