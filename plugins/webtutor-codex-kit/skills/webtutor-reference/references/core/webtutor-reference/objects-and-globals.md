# Объекты и глобальные переменные

## Модель объектов

Официальная документация выделяет:

- базовые объекты языка: `Array`, `Binary`, `ClassObject`, `ClassObjectsArray`, `DataCache`, `Error`, `MethodReference`, `Object`, `PlainSeq`, `SafeArray`, `Stream`, `String`;
- глобальные статические объекты;
- объекты XML-документа и XML-формы;
- объекты базы данных приложения;
- экранные объекты и объекты Web-сервера;
- объекты внешних компонентов и прочие специализированные объекты.

Это не единая JS-иерархия. Один и тот же синтаксис обращения к свойству может скрывать обычный объект, XML-элемент, форму или последовательность с разной семантикой.

## XML-документ

Типичная модель в серверном SP-XML-коде:

```text
Document
└── TopElem
    ├── scalar field (XML-объект со скалярным значением)
    └── child collection / child element
```

Практические правила:

- сохранять сам документ через `doc.Save()`, а не `TopElem.Save()` без подтверждения API;
- не присваивать поле, которого нет в XMD-шаблоне;
- числовой ID приводить через `Int`/`OptInt`;
- для необязательного дочернего элемента использовать безопасный метод получения;
- не сериализовать XML-объекты как plain JS object без специального преобразования.

### Открытие документа по ID

**Проверенная практика:** если в серверном контексте доступен объект `tools`,
предпочитать его обёртку:

```javascript
var objectID = OptInt(rawID);
if (objectID == undefined)
    throw Error("Некорректный идентификатор");

var doc = tools.open_doc(objectID);
var topElem = doc.TopElem;
```

`tools.open_doc()` принимает ID документа напрямую. Это отличает его от
стандартной функции `OpenDoc()`, которой передаётся URL:

```javascript
var doc = OpenDoc(UrlFromDocID(Int(objectID)));
```

Форму `OpenDoc(UrlFromDocID(...))` использовать, когда `tools` недоступен в
текущем контексте или существующий контракт явно требует стандартную функцию.
Не переносить `tools.open_doc()` в другой тип сценария без подтверждения
доступности `tools`.

### Получение дочерних свойств `XmlElem`

`XmlElem` представляет узел открытого XML-документа. Его XML-поля являются
дочерними объектами `XmlElem`, а не свойствами обычного JavaScript-объекта.

Если имя обязательного поля заранее известно из формы или проверенной
XML-структуры, к нему можно обратиться напрямую:

```javascript
var topElem = tools.open_doc(objectID).TopElem;
var code = String(topElem.code);
```

Для динамического имени используйте:

```javascript
var requiredElem = topElem.Child("name");
var optionalElem = topElem.OptChild("comment");

if (optionalElem != undefined)
    alert(String(optionalElem.Value));
```

- `Child(name)` возвращает дочерний `XmlElem` и выдаёт ошибку, если элемента
  нет. Метод также принимает числовой индекс.
- `OptChild(name)` возвращает дочерний `XmlElem` либо `undefined`.
- `GetOptChildValue(name, type, defaultValue)` сразу возвращает приведённое
  значение или значение по умолчанию, если дочерний элемент отсутствует либо
  имеет другой тип. Тип по умолчанию — `"string"`.

Для неизвестной структуры дочерние элементы можно перебрать как абстрактный
массив; `for-in` возвращает сами элементы:

```javascript
for (childElem in topElem)
{
    alert(childElem.Name + ": " + String(childElem.Value));
}
```

Не используйте `PropertyExists(name)` как проверку наличия дочернего
XML-элемента. Этот метод проверяет атрибут или метод самого объекта `XmlElem`.
Для необязательного дочернего элемента проверяйте результат `OptChild(name)`
на `undefined`.

Если поле описано в форме как `MULTIPLE`, обращение по имени может вернуть
`XmlMultiElem`, то есть коллекцию одноимённых дочерних элементов. Не считайте
такое поле одиночным скаляром без проверки формы или фактического XML.

Чтобы сначала получить фактическую XML-структуру объекта WebTutor по ID,
используйте playbook [«Исследовать XML-объект»](../playbooks/inspect-xml-object.md).

Официальные карточки:

- [`XmlElem`](http://docs.datex.ru/article.htm?id=5607317807203771901);
- [`Child()`](http://docs.datex.ru/article.htm?id=5620250451197911731);
- [`OptChild()`](http://docs.datex.ru/article.htm?id=5620276905286592761);
- [`GetOptChildValue()`](http://docs.datex.ru/article.htm?id=5791375928854454938);
- [`PropertyExists()`](http://docs.datex.ru/article.htm?id=5620276892448878714).

### Настраиваемые поля и `tools.get_custom_template`

В установленной версии WebTutor определения настраиваемых полей хранятся в
системном XML-каталоге `custom_templates`. Значения этих полей в объектном
документе обычно находятся в узле `custom_elems`.

Разрешённый набор определений получает системное свойство-метод:

```javascript
var catalogName = "<catalog_name>";
var template = tools.get_custom_template(catalogName);
var fields = template.fields;
```

Поддерживаются контекстные аргументы:

```javascript
var template = tools.get_custom_template(catalogName, topId, sourceTopElem);
```

- первый аргумент выбирает каталог;
- `topId` выбирает вариант шаблона из `items`;
- `sourceTopElem` позволяет вычислить `topId` по пути, заданному шаблоном;
- результатом является разрешённый `XmlElem` или `null`;
- при наследовании метод может объединить базовые `fields` с полями выбранного
  элемента.

Нельзя считать сырой узел `custom_templates.<catalog>` эквивалентом результата
`tools.get_custom_template()`: метод выполняет выбор и объединение контекстного
варианта.

Для диагностического получения результата используйте playbook
[«Исследовать системный объект»](../playbooks/inspect-system-object.md).

## Стандартные объекты SP-XML

У обычных объектов SP-XML могут быть доступны `GetProperty`, `GetOptProperty`, `SetProperty`, `HasProperty`. Безопасное чтение конфигурации выглядит так:

```javascript
var is_dev = AppConfig.GetOptProperty("IS-DEV-MODE") == "1";
var person_id = OptInt(SCOPE_WVARS.GetOptProperty("person_id"));
```

`GetOptProperty` предпочтителен для внешних и необязательных данных. `GetProperty` уместен, когда отсутствие свойства означает нарушение внутреннего контракта.

## Глобальные переменные по контекстам

Официальный индекс содержит более сорока переменных. Ниже — те, которые наиболее важны при разработке серверного кода и отчетов.

| Переменная | Практический смысл | Ограничение |
|---|---|---|
| `AppConfig` | конфигурация приложения | ключ может отсутствовать; использовать безопасное чтение |
| `AppCharset` | кодировка приложения | важна для байтовых строковых операций |
| `AppID`, `AppName`, `AppVersion` | сведения о приложении | не использовать как замену feature detection |
| `AppServerConfig` | конфигурация сервера приложения | не логировать целиком; может содержать чувствительные настройки |
| `CurDate` | текущая дата/время платформы | не считать JS `Date` |
| `CurRequest` | текущий Web-запрос | доступен только в подходящем серверном контексте |
| `CurAuthObject`, `CurAuthObjectUrl` | текущий авторизованный объект | отсутствие авторизации нужно обрабатывать явно |
| `CurThreadAuxData` | дополнительные данные потока | не считать глобальным долговременным хранилищем |
| `DefaultDb`, `DefaultDbName` | база данных приложения | не заменяют проверку схемы каталога/таблицы |
| `GlobalEnv` | глобальное окружение | избегать неявных зависимостей и мутаций |
| `Worker` | контекст worker | использовать только в соответствующем типе запуска |

UI-переменные (`ActiveScreen`, `MainScreen`, `FocusItem`, `AllScreens`, `TopScreens` и другие) не следует использовать в серверном агенте только потому, что они присутствуют в общем индексе.

## Контекстные объекты проекта

Следующие имена встречаются в коде, но не являются универсальными глобалами для любого сценария:

- `Param` — параметры агента/скрипта;
- `SCOPE_WVARS` — параметры Web-формы/отчета;
- `curParams` — параметры текущего исполняемого пользовательского Web-шаблона;
- `oCollectionParams` — параметры remote collection;
- `CurRequest.Session` — данные текущей Web-сессии;
- `tools`, `tools_web` — библиотечные объекты, зависящие от подключенного модуля.

Перед использованием найти рабочий файл того же типа исполнения. Нельзя переносить код remote collection в агент без проверки входов и доступного окружения.

### Параметры пользовательского Web-шаблона

В ASP-файле, который исполняется пользовательским Web-шаблоном, значение
параметра читается из `curParams`:

```javascript
function GetTemplateParam(name)
{
    return tools_web.get_web_param(curParams, name, undefined, 0);
}

var resourceID = OptInt(
    GetTemplateParam("resource_file_id")
);

if (resourceID == undefined)
    throw Error("Не задан параметр resource_file_id");
```

`curParams` содержит параметры именно того объекта Web-шаблона, в контексте
которого выполняется ASP-файл. Если одноименный параметр настроен в другом
шаблоне, `tools_web.get_web_param(...)` его не увидит и вернет переданное
значение по умолчанию.

После чтения параметр нужно явно привести к ожидаемому типу и проверить
результат. Для 64-битного ID использовать `OptInt`/`Int`; при передаче ID в
JSON или URL преобразовывать его в строку без промежуточного преобразования в
`Real`.

Пример формирования ссылки на ресурс базы:

```javascript
var fileURL = "/download_file.html?file_id=" + String(resourceID);
```
